## Server vs client components

Catalog pages are server components. Everything behind auth is a client component.

Not stylistic: the session JWT lives in `localStorage` (`store/auth-store.ts`), so the server
can't read it — an authed page has to render, hydrate, *then* fetch. Don't "fix" an authed page by
making it a server component; it'd have no token. Revisiting that is one change (httpOnly cookie)
that unlocks all of them at once.

In server components fetch in parallel and degrade per section, not per page —
`app/(shop)/page.tsx` is the reference: each section `.catch(() => null)`s independently so one
dead endpoint doesn't blank the route.

## One fetch path

**Every** network call goes through `apiFetch` in `lib/api/client.ts`, wrapped by a typed helper
in `lib/api/*.ts`. Never call `fetch` from a component.

- Transport failures (server down, DNS, offline) become `ApiError` with `code: "NETWORK_ERROR"`,
  not an unhandled rejection. `isNetworkError` / `isServerError` are the predicates.
- The backend's Zod error envelope is parsed into `ApiValidationError.fieldErrors`, ready to feed
  a `react-hook-form` field.
- **Branch on `code`, never on message text.**

Catch specifically. `lib/api/catalog.ts:notFoundToNull` is the pattern — intercept the one code you
handle, let the rest reach an error boundary.

## Stores

`store/*.ts`, zustand. Learned the hard way:

- **A persisted store needs `version` + `migrate`.** `chat-store.ts` shipped without one and a v2
  transcript in `sessionStorage` rehydrated into v3 widgets and crashed the panel. New required
  field on anything persisted → bump the version.
- **Don't persist derived or transient state.** `auth-store` persists only `user` and `token`, not
  `status`, so server render and first client render both start `idle` and guards show a spinner
  instead of flashing protected content.
- **Anything user-scoped clears on logout.** `auth-store.logout()` resets the cart store — a store
  keeping user data across logout leaks it to the next person on that device.
- Distinguish "token invalid" from "network hiccup". `hydrateFromServer` clears the session on the
  first, keeps it retryable on the second. A backend restart must not log everyone out.

## Chat protocol

`lib/chat/protocol.ts` mirrors `backend/src/chat/protocol.ts`. Two copies of one wire format, by
design — the projects share no code.

- **`CHAT_PROTOCOL_VERSION` bumps on both sides in the same change.** A mismatch is a deliberate,
  loud 400.
- It guards the **request only**. Parts already in `chat_messages.parts` and `sessionStorage`
  replay as-is, so **treat every new field on a part as optional** and degrade. A widget assuming a
  field exists will crash on old history.
- Widgets are projected from tool results by the backend's `partMapper`; the model never authors
  them. A widget needing data means adding it to the part type on **both** sides — a prompt telling
  the model to "let the widget show it" is worthless if the wire type has nowhere to put it.

## UI

shadcn/base-ui in `components/ui/` — generated, compose over them rather than editing. Use
`components/common/empty-state.tsx` and `error-state.tsx` instead of new empty/error markup;
`sonner` (`toast`) for transient feedback.

## Known and accepted — not bugs

- **Auth tokens in `localStorage`**, 7-day TTL, no server-side revocation. Readable by any injected
  script. Accepted; it's also why every authed page is a client component.
- **Voice is multilingual, the UI isn't.** The mic transcribes 23 languages and speaks the reply
  back, but the agent, widget copy and catalog are English — a Hindi speaker hears Hindi then reads
  an English product card. Closing it means translating widget payloads and running the agent in
  the target language.
- **Plain `<img>` throughout**, `next/image` deliberately not wired up. Same for all frontend perf
  work: no `revalidate` on catalog server components, no `next/dynamic`, no transcript windowing.
- **Reviews tab restates the aggregate rating.** No real reviews, intentional.
- **No coupons** — backend hardcodes `discount = 0`. No wishlist (removed: no table, no API, and
  the `localStorage` key leaked one user's list to the next on a shared device).
- Eight `react-hooks/set-state-in-effect` lint warnings remain. `bun run lint` is clean of errors;
  the one that cost a real extra render is fixed, the rest are cosmetic.
